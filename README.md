# UNIPROM CRM

**UNIPROM CRM (R1)** — CRM-модуль для ООО «Унипром», автоматизированная система
подбора и сопровождения заказов фильтровального оборудования. Разработан по
техническому заданию «CRM модуль Унипром», редакция 2.0 (документ заказчика,
в репозиторий не включён).

CRM ведёт заявку на изготовление оборудования по всему пути: поступление,
задачи, коммерческие предложения, заключения конструкторского отдела, выпуск
в производство, исполнение и закрытие. Система обменивается данными с 1С и
почтой, импортирует заявки из Excel/CSV, контролирует сроки (SLA) и строит
аналитику.

## Какую задачу решает

Заказ фильтровального оборудования проходит через несколько отделов: продажи,
конструкторский отдел, производство и бухгалтерию. Без единой системы данные по
одному заказу разбросаны по почте, таблицам, 1С и личным заметкам менеджеров. Из-за
этого происходит следующее:

- заявки теряются или дублируются, потому что приходят через сайт, почту,
  вручную и списками в Excel;
- не видно, на каком этапе заказ, кто за него отвечает и что его задерживает;
- коммерческое предложение могут отправить клиенту без согласования
  руководителя или с устаревшей технической частью;
- заказ попадает в производство без подтверждённой оплаты или подписанного
  договора;
- сроки срываются незаметно, потому что о просрочке руководитель узнаёт поздно;
- данные о счетах, оплатах и отгрузках вручную переносят между CRM и 1С.

UNIPROM CRM решает это **единым сквозным процессом вокруг одной сущности —
заявки**. Коммерческие, инженерные и учётные данные привязаны к заявке, а не
к параллельной «сделке». Процесс начинается с поступления заявки и заканчивается
полной отгрузкой, завершением расчётов и оформлением закрывающих документов:

1. **Поступление.** Заявки приходят из четырёх каналов: модуль подбора на сайте,
   ручной ввод, входящая почта (заявку создаёт сотрудник, проверив письмо),
   импорт Excel/CSV. Ключи идемпотентности не дают создать дубли.
2. **Квалификация и КО.** У заявки есть уровень сложности: типовая,
   модифицированное исполнение или нестандартное изделие. Нестандартные заявки
   уходят в конструкторский отдел, где составляют и утверждают техническое
   заключение.
3. **Коммерческое предложение.** КП генерируется в CRM или загружается готовым
   файлом. У КП есть версии. Каждую версию согласует руководитель продаж, и
   только после этого её отправляют клиенту с фиксацией отправки.
4. **Договор и расчёты.** В системе ведутся договорные условия, счета,
   распределение платежей, остатки и просрочки.
5. **Выпуск в производство.** Выпуск возможен только после проверки условий:
   полная или частичная предоплата с разрешением, постоплата, таможенный режим.
   Обычным изменением этапа эту проверку не обойти.
6. **Исполнение и закрытие.** Учитываются частичные отгрузки по каждой позиции.
   Заявку можно закрыть, только когда всё отгружено, полностью оплачено и есть
   закрывающие документы.

Процесс сопровождают задачи и коммуникации, настраиваемые нормативы сроков
с напоминаниями и эскалацией руководителю, двусторонний обмен с 1С (заказы
передаются в 1С, а счета, оплаты и отгрузки приходят обратно), аудит действий
и аналитика «план–факт».

## Пользователи

Система рассчитана на сотрудников ООО «Унипром», до 30 человек одновременно.
С компьютера доступны все функции. С телефона можно работать с заявками и
задачами и согласовывать КП. Каждая роль видит только свою область данных, и
backend проверяет права на каждый запрос, включая поиск, агрегаты, файлы и
экспорт.

| Роль | Кто это | Что видит | Что делает в системе |
| --- | --- | --- | --- |
| `SALES` | Менеджер по продажам | Только назначенные ему заявки | Ведёт карточки, контакты, задачи и переписку, готовит КП, отправляет согласованные версии, сопровождает договор и заказ |
| `SALES_MANAGER` | Руководитель отдела продаж | Все заявки и коммерческие данные | Распределяет заявки между менеджерами, контролирует загрузку и сроки, согласует каждое КП, утверждает коммерческие условия, смотрит аналитику |
| `DESIGN_MANAGER` | Руководитель конструкторского отдела | Заявки, направленные в КО | Ведёт очередь КО, назначает инженеров, расставляет приоритеты, утверждает технические заключения |
| `DESIGNER` | Инженер-конструктор | Назначенные ему инженерные задания | Анализирует исходные данные, готовит техническое заключение, инженерные ревизии и документы |
| `PRODUCTION` | Производство | Заявки, выпущенные в производство | Отслеживает производственные стадии и сроки, видит только необходимый коммерческий контекст |
| `VIEWER` | Наблюдатель, например руководство | Настраиваемая область | Только чтение |
| `ADMIN` | Администратор системы | Все данные | Управляет пользователями, ролями, справочниками, нормативами SLA и интеграциями, просматривает аудит, восстанавливает данные |

Основные экраны интерфейса: дашборд, список заявок и карточка заявки, создание
заявки, задачи, очередь конструкторского отдела, разбор входящей почты, импорт,
аналитика и администрирование.

**Не входит в R1:** телефония, мессенджеры, корпоративный SSO, гарантийный и
сервисный модуль, нативные мобильные приложения, работа без сети. Архитектура
позволяет добавить их позже, не меняя базовую модель заявки.

## Конфигурация

Переменные окружения читаются из `backend/.env`. Полный шаблон с комментариями —
`backend/.env.example` (скопируйте его в `.env` при развёртывании):

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PORT` | порт backend | `3001` |
| `NODE_ENV` | режим (`development` / `production`) | `development` |
| `DATABASE_URL` | подключение к SQLite | `file:./prisma/crm.db` |
| `STORAGE_DIR` | каталог загруженных файлов | `var/storage` |
| `INTEGRATION_TOKEN` | значение заголовка `x-integration-token` | `dev-integration-token` |
| `MAIL_TRANSPORT_URL` | приёмник исходящей почты; пусто — очередь не обрабатывается | пусто |
| `OUTBOX_TARGET_URL` | приёмник событий 1С; пусто — события остаются в `PENDING` | пусто |
| `RATE_LIMIT_MAX` | общий лимит запросов | `1200` |
| `AUTH_RATE_LIMIT_MAX` | лимит попыток входа с одного IP | `30` |
| `RATE_LIMIT_WINDOW_MS` | окно rate limit | `60000` |

Окно rate limit — 60 секунд. Повторный прогон smoke-тестов чаще раза в минуту
даёт `429 RATE_LIMITED`, а серия неверных паролей — `423 LOGIN_LIMIT_EXCEEDED`.

## Аутентификация

1. `POST /api/v1/auth/login` с логином и паролем возвращает JWT.
2. Токен передаётся в заголовке `Authorization: Bearer <token>`.
3. Технические эндпоинты (`/api/v1/integrations/*`, `/internal/*`) требуют
   заголовок `x-integration-token`.
4. В режиме `production` заголовки Dev-режима отклоняются, а заблокированный или
   неактивный пользователь не получает доступ.

## Архитектура API

Поддерживаются два взаимозаменяемых префикса с одинаковой серверной проверкой прав
и области видимости:

- канонический — `/api/v1/...`;
- контрактный — `/api/v1/crm/...` (алиасы для совместимости).

Ключевые группы:

| Группа | Пример маршрутов |
| --- | --- |
| Заявки | `POST /api/v1/applications`, `GET /api/v1/applications/:number`, `POST /api/v1/applications/:number/stage` |
| Задачи и коммуникации | `GET /api/v1/tasks`, `POST /api/v1/applications/:number/activities` |
| КП | `POST /api/v1/applications/:number/quotes`, `POST /api/v1/quotes/:quoteId/send` |
| Конструкторский отдел | `GET /api/v1/engineering/tasks`, `POST /api/v1/engineering/conclusions/:id/approve` |
| Выпуск и исполнение | `GET /api/v1/applications/:number/production-release-check`, `POST /api/v1/applications/:number/close` |
| Импорт | `POST /api/v1/imports/inspect`, `POST /api/v1/imports/upload` |
| Интеграции | `POST /api/v1/integrations/commercial/sync`, `POST /api/v1/integrations/mail/inbound` |
| Аналитика | `GET /api/v1/dashboard`, `GET /api/v1/analytics/plan-fact` |
| Администрирование | `GET /api/v1/users`, `PUT /api/v1/sla/rules`, `GET /api/v1/audit-events` |

Полное описание — `docs/openapi.yaml`.

## Ключевые правила предметной области

- **Идемпотентность.** Создание заявки принимает `Idempotency-Key`; повтор с тем
  же ключом возвращает существующую заявку.
- **Оптимистичная блокировка.** Изменение ресурса требует `lockVersion`; при
  конфликте возвращается `409 VERSION_CONFLICT`.
- **Переходы этапов.** Диаграмма переходов описана в `domain/constants.ts`; выход в
  `TO_PRODUCTION` возможен только через проверку выпуска, обычным endpoint не
  обходится.
- **Условия выпуска.** Полная предоплата, частичная предоплата с ручным
  разрешением, постоплата и таможенный режим проверяются в
  `services/commercial.ts`; фиктивная оплата не создаётся.
- **Закрытие.** Отдельное действие; блокируют неполная отгрузка, незавершённая
  постоплата и отсутствие обязательных документов.
- **Область видимости.** Сотрудник продаж не видит чужие заявки, файлы и агрегаты;
  наружу отдаётся `404`, а не `403`, чтобы не раскрывать существование.
- **Уникальность в БД.** Частичные уникальные индексы для активного выпуска,
  активного коммерческого основания и активного утверждения релиза создаются при
  старте (`lib/integrity.ts`).

## Импорт данных

1. `POST /api/v1/imports/inspect` — загрузка файла, сервер определяет разделитель
   и колонки, возвращает заголовки и выборку. Формат `multipart/form-data`.
2. Пользователь сопоставляет колонки и отправляет
   `POST /api/v1/imports/upload` с полем `mapping`.
3. Предпросмотр показывает ошибки по строкам и сводку по группам.
4. `POST /api/v1/imports/:batchId/commit` создаёт заявки; группа с ошибочной
   строкой не импортируется целиком.

Поддерживаются CSV (UTF-8 и Windows-1251, разделитель определяется автоматически,
кавычки и переводы строк внутри полей) и XLSX (первый лист). Лимит — 5000 строк.
Повторная загрузка принятого пакета не создаёт дублей.

## Доставка очередей (A19, A45)

Воркер запускается вместе с API и каждые `DELIVERY_INTERVAL_MS` обрабатывает две
очереди: письма с КП и события для 1С.

- `MAIL_TRANSPORT_URL` — приёмник исходящей почты. Пока переменная не задана,
  очередь писем **не обрабатывается**: задания остаются в статусе `QUEUED`.
  Это осознанно — попытка отправки без транспорта потратила бы лимит повторов
  и перевела письма в `FAILED` не по вине системы.
- `OUTBOX_TARGET_URL` — приёмник пакетов синхронизации 1С. Пока не задан,
  события остаются `PENDING`.
- `DELIVERY_INTERVAL_MS`, `DELIVERY_TIMEOUT_MS`, `DELIVERY_BACKOFF_BASE_MS` —
  период опроса, таймаут HTTP-запроса и база экспоненциальной задержки.

Повторы повторяются по `backoffMs`, максимум 8 попыток, после чего задание
переходит в конечное состояние и остаётся видимым с причиной. Если результат
доставки письма неизвестен, письмо переходит в `UNKNOWN` и **не отправляется
повторно вслепую** (иначе клиент мог бы получить дубликат).

## Эксплуатационные процедуры (A42, A43, A44)

```powershell
cd backend

# Нагрузка: 30 одновременных пользователей, отчёт по маршрутам и показателям
npm run loadtest
npm run loadtest -- --users 30 --rounds 5

# Резервная копия: база + файлы + манифест с контрольными суммами
npm run backup:create
npm run backup:list
npm run backup:verify -- <каталог комплекта>
npm run backup:restore -- <каталог комплекта> --force

# Миграция копии: снимок до переноса, снимок после, сравнение
npm run migrate:snapshot -- before.json
npm run migrate:verify -- after.json
npm run migrate:compare -- after.json before.json
```

`restore` требует явного `--force` и проверяет контрольные суммы до замены
данных: повреждённый комплект приводит к отказу, а не к «восстановлению»
половины базы. Перед `restore` остановите backend.

## Проверки

```powershell
# Backend
cd backend
npm run typecheck
npm run build

# Модульные тесты чистой логики (без БД и сети): backoff доставки,
# округление денег, контроль суммы распределения
npm test

# Smoke-тесты (136 проверок по HTTP; требуют запущенного backend на порту 3001).
# Прогон занимает больше 60 с, поэтому не совмещайте его с нагрузкой.
npm run smoke

# Нагрузка на 30 одновременных пользователей.
# Запускайте не раньше чем через 60 с после smoke: общий лимит запросов
# (RATE_LIMIT_MAX, окно 60 с) иначе вернёт 429 и A42 упадёт не из-за продукта.
npm run loadtest

# Frontend
cd frontend
npm run typecheck
npm run build
```

Сброс временных счётчиков блокировки входа после неудачных попыток входа:

```powershell
cd backend
npx --yes tsx scripts/reset-login-locks.ts
```
